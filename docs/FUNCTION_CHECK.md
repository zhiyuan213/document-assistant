## 真机反馈后的补充检查

后续用户真机测试仍发现任务404和ZIP保存失败，所以前面的普通样例通过不代表完整真机验收通过。用无效PDF和过短密码在云端复现了失败任务始终404；相同失败流程在本机可正常返回真实失败原因。确切云端原因尚需读取任务到期时间和数据库时区，只读脚本见 `database/diagnostics/pdf_jobs.sql`。

本次统一使用数据库 `CURRENT_TIMESTAMP` 计算初始和完成结果的到期时间，避免在Java与数据库时钟之间混算；不需要修改表结构。这是时间一致性修正，不能在云端重新验证前宣称404根因已经确定。

手机文件操作改为“下载文件”后再由第二个按钮直接调用“打开文件”或“发送/保存到微信”，不在异步下载回调里自动发起文件分享。取消发送不报保存失败；已存在的本地结果不重复复制。新增模拟测试校验调用时机和错误处理，但实际手机保存和分享仍待用户验证。
