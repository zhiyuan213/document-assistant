# Java 文档翻译（验证版）

Java 21 + PDFBox 实现版面读取、文字替换和导出；DeepSeek 负责翻译。
扫描页由 Java 调用镜像内 Tesseract，文字区域重建也由 Java 完成，不依赖 Python 或专业文档翻译 API。

## 部署与配置

1. 重新构建镜像（根目录、backend 两种 Dockerfile 都已更新）。镜像增加法文 OCR 和 Noto 字体。
2. 数据库执行 `database/migrations/012_pdf_translation_jobs.sql`。脚本可重复执行。若使用默认 `SQL_INIT_MODE=always`，启动也会自动创建新表；不会自动修改既有表结构。
3. 沿用 `DEEPSEEK_API_URL`、`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`，无需购买额外翻译接口。
4. 可选 `PDF_TRANSLATION_OCR_LANGS=chi_sim+eng+fra`，默认识别简体中文、英文、法文扫描件。其他扫描原文语言需安装相应 Tesseract 语言包并配置此变量；目标翻译语言与 OCR 原文语言是不同概念。
5. 可选 `PDF_FONT` 指定已安装的目标字体；默认优先原字体，缺字时尝试 Arial/Noto/WenQuanYi。阿拉伯文使用 Java 字形排版生成矢量轮廓。
6. 重新编译小程序并真机预览，避免运行旧的文字翻译页面。

结果保存在 `pdf_translation_job`：PDF、Word 和文本可跨实例访问，完成后保留 30 分钟并定期清理。数据库需要允许约 32MB 的单次写入（建议 `max_allowed_packet` 至少 64MB）。原始文件仅用于当前进程处理，不作为测试夹具或长期文件保存。

## 使用与计费

- 选择文件和目标语言，先估算再确认；仍支持一个文件直接替换另一个。
- 原生 PDF 最多 30 页，扫描页最多 5 页，总提取文字默认最多 200,000 字符，单文件不超过 20MB；页数继承既有环境变量中更低的限制。翻译字符限制独立配置为 `PDF_TRANSLATION_MAX_INPUT_CHARS`（默认 200000，可配置范围 20000–500000），不再受通用 `PDF_AI_MAX_INPUT_CHARS=15000` 限制。
- 单份翻译最多运行30分钟（单次接口调用受自身超时限制），小程序持续查询最多35分钟，任务恢复不会再次提交或扣费。
- 翻译按页/段分批调用模型，每批最多 4,096 输出 Token，完整校验段落 ID，不将截断译文当作成功。
- 预占根据所有批次累计估算，实际按输入 Token + 输出 Token × 4 结算。一份文档计一次每日请求。查询和导出不再次调用模型。
- 请求标识确保同一次提交的网络重试返回原任务，不重复预占或扣费。重新打开页面可以找回任务；不要清除小程序缓存。
- 模型已返回用量后即使排版失败也按实际结算。网络异常未收到模型用量时保留预占，避免把不确定调用当作零成本。
- 进程异常退出不能恢复内存中的原始文档；未完成任务最终标记失败，不自动再次调用模型，预占需核对后处理。部署时避免中断处理中的翻译。

## 输出与效果边界

- 文本：预览、复制或导出 TXT（微信通过发送/保存入口处理 TXT）。
- Word：可编辑译文和来源页码，重新排版，不声称与原 PDF 版式相同。
- PDF：原生文件保留页面大小、页数、图片和图形，只移除文字绘制并在原区域写入译文。追踪颜色、粗体与透明度；字体子集缺字时使用兼容字体并提示。必要时调整字宽，最窄为原字宽的 65%。
- 扫描页必须 OCR 和重建文字区域；复杂底纹、印章压字、图文重叠、低分辨率和复杂表格不能保证无损。扫描页以 144 DPI 重建，不声称图片像素或 PDF 对象不变。
- 原生页面中的图片保持不变，其中的图片文字不会自动替换；混合型页面会提示核对。
- 字体缺失或译文溢出时保留完整文本和 Word，禁用 PDF 下载，不输出错版 PDF；不会静默增页、截断或丢段。
- 暂不安全处理加密 PDF、交互表单、竖排/斜排文字、文字剪裁效果。用户提供的九页样本不是自动流程的效果保证，仍需实际调用模型验收。

## 验证

自动化检查覆盖原生页非文字区域像素、图形/图片和颜色，扫描坐标及文字区域重建、Form XObject、页旋转、模型缺段/重复 ID、溢出、累计用量、任务归属、提交去重、三种下载和前端恢复。

本地扫描测试使用合成识别坐标，未证明真实 Tesseract 识别准确率。真实 DeepSeek、镜像内 OCR、真机上传/打开/分享和复杂文档版式，需要部署后验证。不得使用用户私有文档作为提交到仓库的测试夹具。
