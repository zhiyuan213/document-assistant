# PDF 小程序免自定义域名接入

小程序生产构建使用 `wx.cloud.callContainer`，H5 继续使用 HTTPS 地址。
不需要购买自定义域名或配置 request/uploadFile/downloadFile 域名来完成 PDF 链路。
云托管自身的资源、调用和流量仍按原有套餐计费，并非免费服务。

## 上线配置

1. 在 PDF 项目的云托管控制台确认环境 ID、服务名称，并允许此 PDF 小程序调用该环境/服务。
2. 在 `frontend/.env.production` 填写 `VITE_CLOUD_ENV`、`VITE_CLOUD_SERVICE`。
   `VITE_MP_TRANSPORT=cloud` 开启专用通道；不要把公网域名当作环境 ID，也不要复制证件照的环境。
3. 部署包含 `PdfCloudTransfer` 的新后端，再运行 `npm run build:mp-weixin --prefix frontend`。
4. 微信开发者工具关闭“不校验合法域名”，重新生成预览码并真机测试。

缺少云配置时显示明确提示，不会退回已被微信拦截的默认公网域名。
本机开发默认保留 HTTP；H5 仍受云托管默认域名测试用途的限制，本改动不解决 H5 正式域名问题。

## 大文件及耗时操作

直接云调用只发送较小的 JSON 请求。PDF 的 multipart 请求体以每块 48KiB 的二进制数据转为 base64 后分块上传；
后台重组原始请求，经本机回环地址交给现有 PDF 控制器处理。前端轮询传输状态，再分块取回 JSON 或二进制结果。
因此 PDF 工具、AI 估算/处理、水印预览、翻译下载及报告导出共用现有业务校验和匿名凭证。
仅允许列出的 PDF 路由，不允许任意 URL、支付通知或递归调用。

每次传输均校验凭证和所有者；分块严格校验偏移、大小和重复内容。上传分块可重试，业务处理不自动重复提交。
输入上限 64MiB（业务接口仍限制单文件 20MiB、总文件 60MiB），输出传输上限 110MiB。
每实例最多八个传输，每个所有者最多两个，后台并行执行两个，传输及残留文件 30 分钟清理。
客户端正常结束会立即删除中转文件，原始处理结果仍按现有的 30 分钟策略保留。

当前 PDF 结果和新传输状态都依赖实例本地存储，因此部署保持**单实例**。
扩容前必须把中转及 PDF 结果改为共享存储、持久化状态和分布式任务队列。
分块方案会增加请求次数，20MiB 文件约需 427 次上传调用，速度和流量成本需要真机测量。
这是一条无需新增域名和对象存储配置的兼容路线；若大文件频繁使用，应再评估云存储直传方案。

## 验证范围

自动检查覆盖分块重组、重复分块、所有者隔离、路由白名单、原接口状态码、认证头、二进制结果和前端云调用。
不得将成功构建等同于微信真机验证。待测：小文件/20MiB 合成 PDF 上传，拆分 ZIP、PDF/Word 打开及分享，
AI 估算/报告导出、翻译轮询，网络中断及过期恢复。只使用合成文档，不上传私人文件作测试。
